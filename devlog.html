4주 차 — 운영 성숙: 비용, 재해 대비, 무료 이전

커밋 수는 적지만 인프라가 가장 많이 움직인 주입니다.

  • 07.14빌드 캐시 68GB 발견 · 정리(디스크 76% → 19%), 배포 검사 워밍업, 이상 없는 정기 검사 LLM 생략(호출 ⅔ 절감), VM 다운사이징(월 $140 → $49), 리포트 문구 전면 한글화
  • 07.15오프박스 백업 · 복원 리허설 · 런북, VM 자체 경보, 외부 uptime 모니터 — 재해 대비 4종 완성
  • 07.17GCP → Oracle Cloud 무료 이전 — ARM 재빌드, DB 복원, DNS 컷오버. 런북이 그대로 실전 절차가 됐고 서버비가 0원이 됐습니다
  • 07.18–19홈 리디자인, 브랜드 마크 확정, 다크모드 전면 적용
  • 07.20문서 현행화, 콘솔 에러 감점화 — “점수는 후하게, 판정은 엄격하게”의 무른 지점 보강
이 주의 사건

홈 리디자인 배포가 자기 검사에서 59점 F를 받았습니다 — 시나리오가 옛 로그인 URL을 보고 있었습니다. 게이트 → 장애 감지 → Discord 경보 → 수정 → 99점 복구까지, 도구가 자기 회귀를 잡은 첫 실전 사례였습니다.

그리고 VM 다운사이징 후 Lighthouse 성능이 99 → 86으로 떨어졌는데, 서비스가 아니라 측정기의 CPU가 줄어든 것이었습니다. 절대값이 아니라 추이가 목적임을 재확인했습니다.

5주 차 — 조사 에이전트

“점수가 떨어졌다”에서 “왜 떨어졌는지”로. 장애가 감지되면 에이전트가 자동으로 조사해 원인을 판정하고 Discord로 보고합니다. 평가셋 없이는 한 줄도 믿지 않는다는 원칙으로, 구현보다 평가 체계를 먼저 만들었습니다.

  • 1단계근본 원인 7유형 분류 체계, 평가셋 175건(유형당 25건, dev 91 / test 84 분리)과 채점기 — 실제 스캐너 의미론으로 재보정
  • 2단계조사 루프 · 도구 상자 · 트레이스, 결정론 폴백과 신뢰도
  • 3단계라우터 정책, 증거 카드 렌더러, LLM 판단 정책과 에스컬레이션
  • 4단계운영 연결 — DB 도구 상자, 트레이스 저장, 장애 훅, 조사 API · 결과 카드 UI · Discord 요약
이 주의 사건

도그푸딩 통과 — 운영에 지연을 주입해 장애를 일으키자 에이전트가 자동 조사를 돌아 server_slow를 정확히 판정하고 Discord까지 보고했습니다. 그 과정에서 재현 판정 결함 2건을 스스로 드러내 수정했습니다. 남은 것은 나머지 원인 유형 도그푸딩과 게이트 승격입니다.
